----------------------------------------------------------------
7. VARIABLES DE ENTORNO DE PRODUCCIÓN
----------------------------------------------------------------

Crear archivo .env en la raíz (NUNCA subir a Git):
  GESTAERP_ENV=production
  GESTAERP_SECRET_KEY=<clave_aleatoria_32+_caracteres>
  GESTAERP_DB_PEPPER=<pepper_aleatorio_32+_caracteres>
  GESTAERP_LOG_LEVEL=info

GENERAR CLAVES ALEATORIAS (PowerShell):
  -o "GESTAERP_SECRET_KEY = $([System.Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 })))"
  -o "GESTAERP_DB_PEPPER   = $([System.Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 })))"

IMPORTANTE: En producción, estas claves DEBEN ser únicas.
           El código aborta si se detecta valor por defecto.

----------------------------------------------------------------
8. VERSIONAMIENTO (CRÍTICO)
----------------------------------------------------------------

SEMANTIC VERSIONING:
  - PATCH (1.0.0 → 1.0.1): Fix de bugs menores
  - MINOR (1.0.0 → 1.1.0): Nueva funcionalidad (retrocompatible)
  - MAJOR (1.0.0 → 2.0.0): Cambio importante / rompedor

COMANDOS DE BUMP DE VERSIÓN:
  npm run bump:patch   # 1.0.0 → 1.0.1 (fix de bug)
  npm run bump:minor   # 1.0.0 → 1.1.0 (nueva feature)
  npm run bump:major   # 1.0.0 → 2.0.0 (gran cambio)

ESTOS COMANDOS ACTUALIZAN SIMULTÁNEAMENTE:
  - package.json
  - src-tauri/tauri.conf.json
  - src-tauri/Cargo.toml

----------------------------------------------------------------
9. CI/CD — GITHUB ACTIONS (GRATUITO)
----------------------------------------------------------------

FLUJO COMPLETO DE RELEASE (después de cada cambio):

  1. Bump de versión:
     npm run bump:patch    (o minor/major según el cambio)

  2. Commit + Tag + Push:
     git add -A
     git commit -m "release: vX.Y.Z"     # X.Y.Z es la versión real
     git tag vX.Y.Z
     git push origin main --tags

  3. GitHub Actions se dispara automáticamente:
     - Compila en Windows (runner gratuito)
     - Firma los binarios
     - Crea Release en GitHub con instalador .exe
     - Genera latest.json para Tauri Updater

  4. Los clientes reciben la actualización automáticamente:
     - Abren la app
     - Verifica nueva versión
     - Descarga e instala solo

----------------------------------------------------------------
10. CONFIGURACIÓN DE SECRETS EN GITHUB
----------------------------------------------------------------

URL: https://github.com/johanalexandercabezas/GestaERP/settings/secrets/actions

SECRETS REQUERIDOS:
  TAURI_SIGNING_PRIVATE_KEY         = Clave privada del updater
  TAURI_SIGNING_PRIVATE_KEY_PASSWORD = Contraseña de la clave
  GESTAERP_PRODUCTION_SECRET        = Clave de producción
  GESTAERP_PRODUCTION_PEPPER        = Pepper de producción

GENERAR CLAVES DE FIRMA DEL UPDATER (una sola vez):
  npx tauri signer generate -w C:\Users\TuUsuario\.tauri\gestaerp.key

Esto genera:
  - Clave privada: C:\Users\TuUsuario\.tauri\gestaerp.key (guardar en GitHub)
  - Clave pública: (mostrada en consola, copiar a tauri.conf.json)

REEMPLAZAR EN src-tauri/tauri.conf.json:
  "pubkey": "REEMPLAZAR_CON_CLAVE_PUBLICA_TAURI"
  → pegar la clave pública generada

----------------------------------------------------------------
11. BACKUP DE LA CLAVE DE FIRMA
----------------------------------------------------------------

La clave privada TAURI_SIGNING_PRIVATE_KEY es MUY importante.
Si se pierde, los clientes no podrán actualizar automáticamente.

GUARDAR EN LUGAR SEGURO:
  - Password manager de la empresa
  - Almacenamiento cifrado (no en GitHub)

----------------------------------------------------------------
12. GENERAR LICENCIAS PARA CLIENTES (KEYGEN)
----------------------------------------------------------------

El keygen es una herramienta interna para generar licencias.
NO se distribuye a clientes.

BUILD DEL KEYGEN:
  cd src-tauri
  cargo run --bin generate_keys

USO:
  Ejecutar: Generar Licencia.bat (en src-tauri/keygen/)
  Comandos: generar, listar, revocar, validar, buscar, stats

REQUISITO: La GESTAERP_SECRET_KEY del keygen DEBE coincidir
           con la de producción.

17. RESOLUCIÓN DE PROBLEMAS COMUNES
----------------------------------------------------------------

P: El build falla con "sqlcipher.lib not found"
R: La feature sqlcipher requiere la librería del sistema.
   Se usó "bundled" (SQLite estándar). Para cifrado real,
   instalar SQLCipher o usar features=["bundled-sqlcipher"]
   con OpenSSL disponible.

P: Vitest falla con "describe undefined"
R: Vitest 4.x tiene un bug. Se usa Vitest 3.2.7 (estable).
   No actualizar a 4.x sin verificación.

P: "No autorizado: debe iniciar sesión"
R: El comando requiere sesión activa. Solo los comandos de
   licencia/login/setup son públicos.

P: El login no muestra la interfaz
R: Verificar que no haya errores de hooks en consola.
   El useMemo fue eliminado por violar reglas de hooks.

P: Los botones de soporte no abren nada
R: Se usa el plugin opener de Tauri (openExternal). Verificar
   que tauri-plugin-opener esté en Cargo.toml y main.rs.
