4. ESQUEMA DE BASE DE DATOS (SQLite encriptado)
================================================================================

Tablas principales:

1. settings
   - key (PK), value

2. users
   - id (PK), username, password, full_name, role, active, created_at
   - Roles: admin, cashier

3. licenses
   - id (PK), license_key, plan, activated_at, expires_at, max_users, active

4. products
   - id (PK), sku, name, description, price, cost, stock, min_stock, max_stock
   - iva_percent, unit (UNIDAD/SERVICIO), active
   - Índice único: sku

5. customers
   - id (PK), name, doc_type, doc_number, phone, email, created_at

6. suppliers
   - id (PK), name, nit, phone, email, doc_type, city, address
   - payment_method, bank_account, iva_responsible
   - offers_credit, credit_days, credit_limit, created_at

7. employees
   - id (PK), name, doc_type, doc_number, position, base_salary
   - transport_allowance, payment_frequency, risk_level
   - phone, email, city, address, hire_date
   - eps, arl, afp, ccf, has_social_security, department, active, created_at

8. cash_registers
   - id (PK), user_id, open_date, close_date, initial_balance
   - current_balance, final_balance, status

9. sales
   - id (PK), user_id, customer_id, total, payment_method, created_at

10. sale_items
    - id (PK), sale_id, product_id, quantity, unit_price, total_price

11. purchases
    - id (PK), user_id, supplier_id, supplier_name, invoice_number, total, created_at

12. purchase_items
    - id (PK), purchase_id, product_id, product_name, description
    - quantity, unit_cost, total_cost, iva_percent, unit

13. expenses
    - id (PK), user_id, description, amount, category, payment_method, created_at
    - supplier_id, supplier_name

14. receivables
    - id (PK), customer_id, customer_name, sale_id, total, paid, status, created_at

15. receivable_payments
    - id (PK), receivable_id, amount, payment_method, created_at

16. inventory_movements
    - id (PK), product_id, movement_type, quantity, unit_price, reason, created_at

17. physical_counts
    - id (PK), user_id, status, notes, created_at

18. physical_count_items
    - id (PK), count_id, product_id, theoretical_qty, counted_qty, difference, adjusted

19. payroll_entries
    - id (PK), employee_id, period, payment_frequency, days_worked
    - basic_salary, transport_allowance, overtime hours (day/night/sunday/holiday)
    - total_earnings, health_deduction, pension_deduction, net_salary, created_at

20. calendar_notes
    - (definido en calendar_notes.rs)

21. notifications
    - (definido en notifications.rs)

22. schema_migrations
    - version (PK), applied_at

Tablas eliminadas por reset_database (preservan estructura):
- sales, sale_items, purchases, purchase_items, expenses, receivables
- receivable_payments, inventory_movements, payroll_entries, physical_counts
- cash_registers, calendar_notes, notifications

Datos eliminados por reset_database:
- productos/servicios de prueba, clientes de prueba, proveedores de prueba
- empleados de prueba, migraciones, usuarios adicionales

Datos conservados por reset_database:
- settings (nombre_negocio, nit, telefono, direccion, ciudad, email, logo_path, etc.)
- licenses
- usuario admin (admin/admin123)
- productos reales del negocio
- servicios reales

10. NOTAS DE AUDITORÍA
================================================================================

- Base de datos encriptada con clave hardcodeada: GestaERP2026Encrypt!
- Todos los comandos Rust son invocados desde React via Tauri invoke()
- El sistema de licencias controla módulos visibles
- El módulo Servicios es siempre visible
- El comando reset_database elimina historial pero conserva datos maestros
- Tiene sistema de migraciones versionadas (schema_migrations)
- Tiene sistema de backups automáticos
- Tiene validaciones de stock y stock mínimo en POS
- Tiene impresión de tickets HTML
